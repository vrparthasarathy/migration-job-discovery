# Review Checklist

Internal review of the `propose-tracker-updates/` skill folder. Not sent to anyone. Use it as a reviewer who has not seen the folder before. Mark each item pass or fail. This is the stand-in for automated checks; no tool runs it. Every item stays unticked until a fresh review passes it.

Testing policy (user decision, 2026-11-15): behaviors are checked by reading the files and by the user's manual testing in the client environment on real use cases, with results recorded against the version they cover. No Copilot run has been made for this folder, and nothing here claims one. Items that need a real run say so.

- [ ] [B01] `SKILL.md` makes a first run `add` the use case, keyed by its use case ID, with name, vendor, specification link, version and source revision, and never writes a central reference (`UC-###` or `QN-####`); with no vendor known it asks the lead once, invents none and writes no keyed row for that use case. The example file's Use Cases rows do this under a fictional vendor. Needs a real run to confirm what Copilot does.
- [ ] [B02] `SKILL.md` has a source-screening mode that runs over the whole inventory and its source locations before any specification exists, suggests `source_status` (`not-located`, `empty` or `uncertain-mapping`), `blocked_reason`, `source_note` and `source_owner` (the inventory's named owner, otherwise `unassigned`), takes `inventory:<row>` or `source-screen:<path>` as the source with no specification anchor, never writes `confirmed-unavailable`, and treats supporting documents as preliminary support that never verifies the source. Needs a real run to confirm what Copilot does.
- [ ] [B03] `SKILL.md` makes every open question one Questions `add` per use case keyed `<use-case-id>/Q<n>` with `spec_refs` `<use-case-id>/Q<n>@v<version>`, the exact latest wording in `current_spec_text` and a source anchor with version, writes no shared answer and no link or group rows, and leaves similarity checking to others. The example file has one such record for each of Q1 to Q6.
- [ ] [B04] `SKILL.md` makes a revised specification `set` `current_version` with `base_value`, `set` `last_change_class` (behavior-change or non-behavior-change) and, separately, `set` `grouping_impact` (could-affect, not-expected or unknown) with the short reason in the row's `reason`, never treat `unknown` as no impact, suggest an answered question as incorporated, and give the same rows with no duplicate record on a rerun with the same input. Needs a real run to confirm what Copilot does.
- [ ] [B05] `SKILL.md` keeps a reworded question's row and identity, writes the new wording to `current_spec_text` with `text_review` `wording-edit` or `possible-meaning-change`, never writes `question_text`, the answer or its status, never withdraws, replaces or supersedes a released row, and flags a possible meaning change for a lead.
- [ ] [B06] `SKILL.md` and the contract copy agree on the field classes: no forbidden or computed field is ever written, human-owned fields only as `suggest` on an existing record or an initial suggestion on an `add`, no `link` operation, and the lead's `grouping_impact_lead` is never written. The example file contains none of these.
- [ ] [B07] `SKILL.md` leaves a value blank when its evidence does not show it, and requires a `source` on every row: a specification path with `@v<version>#<anchor>`, or `inventory:<row>` or `source-screen:<path>` for screening rows; supplied items count only through the specification that records them. Every row of the example file has a source with a version and an anchor.
- [ ] [B08] `SKILL.md` and the example follow the contract's file format (UTF-8 without BOM, RFC 4180, LF, the 12 proposal columns, composed `update_id`), rewrite only the Use Cases and Questions rows in `tracker-updates/<proposal-id>/tracker-updates.csv`, and never release or apply anything.
- [ ] [B09] The report in `SKILL.md` lists content with no row, supplied items not yet in a specification, rows without a source, unread files, use cases with an unassigned source owner or only document support, and use cases whose behavior changed with the suggested grouping impact, and says a lead reviews it all.
