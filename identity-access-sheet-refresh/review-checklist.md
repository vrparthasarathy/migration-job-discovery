# Review Checklist

Internal review of the `refresh-identity-access-sheet/` skill folder. Not sent to anyone. Use it as a reviewer who has not seen the folder before. Mark each item pass or fail. This is the stand-in for automated checks; no tool runs it. Every item stays unticked until a fresh review passes it.

Testing policy (user decision, 2026-11-15): behaviors are checked by reading the files and by the user's manual testing in the client environment on real use cases. No Copilot run has been made for this folder, and nothing here claims one. Items that need a real run say so.

- [ ] [B01] `SKILL.md` pairs a sheet row and a finding on use case, normalized endpoint and normalized environment; gives `unchanged` only when no tracker cell differs and `evidence_refs` was complete, `corrected` when the source contradicts or standardizes a value, `evidence_refs` is filled, a blank `unknowns` is filled or `auth_type` is set or corrected, and keeps the developer's text where the source is silent and no rule sets the value. When `auth_type` is set or corrected, `proposed_access` is rewritten to the request that type calls for and `permissions_to_confirm` keeps the developer's entries and adds the ones the source does not show. The output's `auth_type` is only `website-sign-in`, `api-credential`, `other` or `unknown`: the type the source shows, else the kind the developer's free text unambiguously names (sign-in, SSO or login page; API key, token or credential), else `unknown`, with the row `corrected` and the original wording listed in the report by row and column. The example's first row is `corrected` (method, redirects and access contradicted; input `auth_type` `public page, no login` becomes `unknown`; `proposed_access`, `permissions_to_confirm`, `unknowns` and evidence filled). No example file shows `unchanged`; the rule says a rerun on the refreshed output gives it. Needs a real run to confirm what Copilot does.
- [ ] [B02] `SKILL.md` pairs a loose match only when one-to-one and unambiguous (one `corrected` row, the pairing and the difference in the report), and with several candidates pairs nothing, gives `not in source` rows and a `new` row, lists a possible match, and never uses a row or finding twice. The ambiguous example has two loose candidates (`prod`, `test`) for one finding and gives two `not in source` rows and one `new` row.
- [ ] [B03] `SKILL.md` adds a `new` row for an unpaired finding with `vendor` and `use_case_ref` from the use case's other rows, every spec field from the source, `auth_type` from the evidence (`unknown` where none), `proposed_access` and `permissions_to_confirm` by the rules of that type with every permission the source does not show listed, `unknowns` listing what the source does not show including, where a pipeline or build identity could serve, `reuse of an existing CI identity: unconfirmed`, and every other human, forbidden and extra column blank. The ambiguous example's `new` row does so.
- [ ] [B04] `SKILL.md` copies a row with no source evidence unchanged as `not in source`, never deleted or guessed at, with the reason in the report, for a missing source, a missing `external_tools.md` or `logic.md`, a use case with no folder and an endpoint the source does not show. - [ ] [B05] `SKILL.md` copies human, forbidden, computed and extra columns exactly as typed, never generates a forbidden value and leaves human columns blank on a `new` row, and lists in the report, by row and column and without changing them, every human-owned or forbidden value outside its allowed list or format (`request_status` or `verification` outside its list, a date that is not `YYYY-MM-DD`, an `expected_availability` that is neither a date nor `unknown`). In the examples every such column of every input row equals the output (compare mechanically).
- [ ] [B06] `SKILL.md` reports a literal credential as its location and `value withheld`, with no part, length or masked form anywhere, replaces a secret typed in a cell with `value withheld` and names the cell, writes identity references as `NAME (runtime value unknown)` and never a value from a runtime, a log or a CI setting, and lists reuse of an existing CI identity in `unknowns` as `reuse of an existing CI identity: unconfirmed`, never as certain.
