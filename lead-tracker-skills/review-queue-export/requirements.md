# Requirements: Review Queue Export

The shared rules are in the [root requirements](../../requirements.md#requirements) and the [group's](../requirements.md#requirements).

## Requirements

- Goal: do the job of the Review CSV Exporter on CSV files in the client environment, where executables are blocked and nothing may be installed or run: the skill is Markdown only and Copilot does the work by reading and writing the named files.
- It follows the explicit procedure in [contract.md](contract.md#contract), derived from the Review CSV Exporter's contract, requirements and Behavior in `tracker-tools`, and keeps its output file names and shapes so the other skills and the review flow read them unchanged.
- It writes nothing into the tracker, SharePoint or any input file, invents nothing, and stops with a named error instead of guessing.
- Every output starts with a count line; rows in must equal rows classified.
- Plain Markdown skill for GitHub Copilot in VS Code agent mode. The folder holds no code and no Craft term.

## Must match the source

- The Review CSV Exporter's contract and Behavior, and the Tracker Data Contract: columns, owner classes, references, statuses and the proposal and export formats. The contract and schema copies in the skill folder are byte-identical to the Tracker Data Contract's files, and the table rules copies are byte-identical to the master.
- The golden expected outputs, generated by running the reference tool on the fictional fixtures, with the normalizations listed in `golden/COMPARE.md` (for example `content_digest` is `unhashed`, link scores are compared with a tolerance).

## Must not

- Include a Craft term, command or file in the skill folder, or any code to run.
- Use a real vendor name, real data or a secret in a fixture.
- Change the Tracker Data Contract, the reference tool or another skill's output.

## Need not match

- The reference tool's byte-for-byte output, its SHA-256 digests, or its speed: rows and decisions must match, wording may vary.

## Verification

- A `review-checklist.md` with one item per behavior and a rules scan, golden fixtures with expected outputs shipped as text and compared by the lead (`golden/COMPARE.md`), and the user's manual client-environment testing recorded as user-reported evidence for the version tested. No Copilot run is claimed.

## Known risks

- **Output varies.** Copilot output differs between models and runs; the rows and decisions are checkable, the wording is not fixed.
- **Scale.** About 300 use cases and thousands of proposal rows can exceed Copilot's context; the skill chunks its work and the backlog item `skill-scale-limits` measures the real limits.
- **No arithmetic guarantee.** Copilot cannot compute SHA-256 and approximates similarity scores; the skill avoids digests and marks scores approximate.
- **Weaker than the reference tool.** No byte determinism, no digest tamper check, and no hard guarantee on a very large input.
