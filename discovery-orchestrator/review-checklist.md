# Review Checklist

Internal review of the `run-discovery/` skill folder. Not sent to anyone. Use it as a reviewer who has not seen the folder before. Mark each item pass or fail. This is the stand-in for automated checks; no tool runs it. Every item stays unticked until a fresh review passes it.

Testing policy: behaviors are checked by reading the files and by manual testing in the client environment on real use cases, recorded against the version they cover. No Copilot run has been made for this folder, and nothing here claims one. Items that need a real run say so.

- [ ] [B01] `SKILL.md` has the skill state the use case, its vendor and source location read from the folder, and the four stages in order (source screening, identity and access, behavior documentation, workflow recommendation) before it runs them. Needs a real run to confirm what Copilot does.
- [ ] [B02] `SKILL.md` runs the stages one after another through `propose-tracker-updates` (source screening), `discover-identity-access`, `document-job-behavior` then `propose-tracker-updates` (specification update), and `recommend-workflows`, each writing only its own rows in its own file; its own write is the `use-case-index.csv` row (five columns `use_case_name,slug,vendor,folder,spec`, root-relative `folder`), never a proposal file and never a review cell.
- [ ] [B03] `SKILL.md` never asks for a proposal ID and derives `uc-<vendor-slug>-<use-case-slug>` (slug rule as the contract), stops before any stage and writes nothing on a duplicate ID in a different folder, writes or updates the folder's index row, and asks once, in one message, only for what it cannot read or derive (repository root, vendor and source location when absent, export folder, proposals root, exporter path, review output folder, the lead's name and date), never inventing them or taking the name or date from the environment.
- [ ] [B04] `SKILL.md` skips stages 3 and 4 when `source_status` is `not-located` or `empty`, says why, does not skip for `uncertain-mapping`, and records the blocker through stage 1.
- [ ] [B05] `SKILL.md` sets the row's `spec` after behavior documentation (blank for a folder skipped for no usable source), then runs `recommend-workflows` over every index row with the fixed proposal ID `recommendations` (never asked for), showing the full list once with the partial-list warning and running only after the lead confirms.
- [ ] [B06] `SKILL.md` runs `node <exporter path>/src/main.ts export-review --export <dir> --proposals <root> --out <dir>` (compare with the exporter's `contract.md`), stops and shows the error on exit 1, and reports per stage what was proposed, skipped or blocked, then the counts including rejected rows. The four output file names match the exporter's.
- [ ] [B07] `SKILL.md` runs only the chosen next folder, does not rerun earlier folders unless the lead asks, and says their rows stay in the review files.
- [ ] [B08] `SKILL.md` forbids writing to the tracker, releasing a question, recording an acknowledgement or a decision on its own, applying a change, editing a proposal file or another skill's output.
- [ ] [B09] `SKILL.md`, after the export, hands the review folder, the lead's name and the date to `record-review-decisions`, states that the walk and every decision are recorded there, records no decision, reads and edits no review cell and does not rerun the exporter after a decision.
- [ ] [B10] `SKILL.md` passes a request to accept all plain `add` rows of one use case to `record-review-decisions` and records nothing itself.
- [ ] [Rules] The folder holds only `SKILL.md`, front matter `name: run-discovery` equal to the folder name, a description with trigger phrases, `user-invocable: true`, and the five installed-beside skills named are `propose-tracker-updates`, `discover-identity-access`, `document-job-behavior`, `recommend-workflows` and `record-review-decisions`. Wording scan: no Craft term, command or file (`craft`, `task`, `acceptance`, `component`, `README`, `contract.md`, `requirements.md`, `/craft:`), `use case` for the business unit, `job` or `script` only for the vendor's script, no secret, no real vendor data.
